## App layout

```text
Acme/
├─ Project.swift                  Tuist project: an app target per platform
├─ Manifest.swift                 Your project's settings (commit it)
├─ Tuist/                         Shared Tuist helpers
├─ Packages/
│  ├─ AcmeApp/                    The SwiftUI app
│  ├─ AcmeKit/                    Logic shared with the server, and its tests
│  └─ AcmeServer/                 With the server: the Hummingbird server
├─ Dockerfile                     With the server: builds AcmeServer for Linux
├─ Sources/  Resources/           App entry point, icon, privacy manifest
├─ Config/                        Build settings and version numbers
├─ UITests/                       Screenshot UI tests
├─ fastlane/                      Signing, TestFlight and App Store lanes
├─ Gemfile  Gemfile.lock          fastlane's Ruby gems
├─ .env.example                   App Store Connect and match secrets for local runs
├─ Marketing/                     Press kit: icons exported from your app icon
├─ Scripts/                       Linting, file header, icons and versioning
├─ .swiftlint.yml  .swift-format  Lint and format rules
├─ .github/workflows/             CI
├─ .devcontainer/                 Linux dev containers, one per Swift version
├─ .agents/                       Notes and skills shared by AI coding agents
├─ .claude/                       Claude Code settings
├─ .gitattributes                 Git LFS for images
├─ AGENTS.md                      Instructions for AI coding agents
├─ CLAUDE.md                      Symlink to AGENTS.md, for Claude Code
├─ LICENSE
├─ Makefile  .mise.toml
└─ README.md  CHANGELOG.md
```

`AcmeApp` holds the SwiftUI code and `AcmeKit` the code without UI, so `AcmeKit` builds
everywhere Swift does and the server can use it. See [Packages](/docs/reference/manifest/#packages)
to lay them out differently.

Each platform you chose gets its own app target in `Project.swift`. They link `AcmeApp` and
share one bundle ID.

The Xcode project is generated by [Tuist](https://tuist.dev) and isn't committed. Run
[`taylr project generate`](/docs/cli/project/generate/) after pulling changes.

## What you can leave out

Most of these files come from a setting in the [manifest](/docs/reference/manifest/), so a
project only has the ones it uses. Your
[project defaults](/docs/cli/profile/#project-defaults) set them for every new project, and
`create`'s arguments for one.

| Setting | Files |
| --- | --- |
| [`appStoreConnect`](/docs/reference/manifest/#app-store-tools) | `fastlane/`, `Gemfile`, `.env.example`, Ruby in `.mise.toml` |
| [`screenshots`](/docs/reference/manifest/#app-store-tools) | `UITests/` |
| [`pressKit`](/docs/reference/manifest/#press-kit) | `Marketing/`, `Scripts/generate-icons.sh`, uv in `.mise.toml` |
| [`lint`](/docs/reference/manifest/#lint) | `.swiftlint.yml`, `.swift-format`, and each tool in `.mise.toml` |
| [`header`](/docs/reference/manifest/#file-header) | `Scripts/header.mustache`, `Scripts/header.sh` |
| [`ci`](/docs/reference/manifest/#ci) | `.github/workflows/` |
| [`devcontainer`](/docs/reference/manifest/#swift-versions) | `.devcontainer/` |
| [`gitLFS`](/docs/reference/manifest/#settings-for-every-project) | `.gitattributes` |
| [`agents`](/docs/reference/manifest/#agents) | `.claude/` and `CLAUDE.md` for Claude Code |

## Swift package layout

```text
Acme/
├─ Package.swift                  Supported platforms are the ones you chose
├─ Manifest.swift                 Your project's settings (commit it)
├─ Sources/Acme/
├─ Tests/AcmeTests/               Swift Testing
├─ Scripts/                       Linting and file header
├─ .swiftlint.yml  .swift-format  Lint and format rules
├─ .github/workflows/             CI
├─ .devcontainer/                 Linux dev containers, one per Swift version
├─ .agents/                       Notes and skills shared by AI coding agents
├─ .claude/                       Claude Code settings
├─ AGENTS.md                      Instructions for AI coding agents
├─ CLAUDE.md                      Symlink to AGENTS.md, for Claude Code
├─ LICENSE                        MIT, unless you chose another
├─ Makefile  .mise.toml
└─ README.md  CHANGELOG.md
```

Create one with [`taylr package create`](/docs/cli/package/create/). A package has no
Xcode project, signing or fastlane. Its CI builds and tests on macOS for each platform you
chose, and on Linux, Windows, Android and Wasm, and runs
[`taylr package validate`](/docs/cli/package/validate/). Its everyday commands are in
[`taylr package`](/docs/cli/package/).

## Git layout

taylr sets up git in one of two ways. Choose one with the **Git** question in
[`project create`](/docs/cli/project/create/) or [`package create`](/docs/cli/package/create/),
or with `--git-layout`. Set your usual choice with `git.layout` in your
[project defaults](/docs/cli/profile/#project-defaults).

**Worktrees** (`worktrees`, the default): `Acme/` isn't a checkout itself. It holds a bare
repository and a folder for each branch you check out. You can work on several branches at
once, or give each coding agent a branch of its own, without stashing or cloning again.

```text
Acme/
├─ .bare/                         The repository
├─ .git                           Points git at .bare/
└─ main/                          The main branch: your project
```

Work inside a branch's folder: `cd Acme/main`. To check out another branch, add a folder next
to it from `Acme/`:

```sh
git worktree add -b feature-login feature-login
```

Each branch folder is a complete project. Run `mise trust` and then
[`taylr project generate`](/docs/cli/project/generate/) in it to get its own Xcode project.
Remove it with `git worktree remove feature-login` when you're done.

**Single checkout** (`single`): taylr creates the GitHub repository and clones it into `Acme/`,
an ordinary checkout. Without GitHub, `Acme/` is a new local repository.

## Everyday commands

| Command | Does |
| --- | --- |
| [`taylr project generate`](/docs/cli/project/generate/) | Generate the Xcode project and open it (apps). |
| [`taylr project test`](/docs/cli/project/test/) | Run the tests. |
| [`taylr project lint`](/docs/cli/project/lint/) | Check and fix code with SwiftLint and swift-format. |
| [`taylr project build`](/docs/cli/project/build/) | Build from the command line. |
| [`taylr project clean`](/docs/cli/project/clean/) | Remove build output and generated files. |
| [`taylr project validate`](/docs/cli/project/validate/) | Check that `Manifest.swift` and the project agree, and the agent files are linked. |

## Signing and release

Code signing uses [fastlane match](https://docs.fastlane.tools/actions/match/), with
certificates in the [storage](/docs/cli/profile/#certificates-storage) from your
[profile](/docs/cli/profile/). These commands need fastlane, which every app has unless its
manifest sets [`appStoreConnect: nil`](/docs/reference/manifest/#app-store-tools).

| Command | Does |
| --- | --- |
| [`taylr project register`](/docs/cli/project/register/) | Register the app and its app group with Apple. |
| [`taylr project certs`](/docs/cli/project/certs/) | Fetch signing certificates and provisioning profiles. |
| [`taylr project add-device`](/docs/cli/project/add-device/) | Register a test device. |
| [`taylr project beta`](/docs/cli/project/beta/) | Build and upload to TestFlight. |
| [`taylr project metadata`](/docs/cli/project/metadata/) | Upload the App Store listing from `fastlane/metadata/`. |
| [`taylr project privacy`](/docs/cli/project/privacy/) | Publish your App Privacy answers. |
| [`taylr project screenshots`](/docs/cli/project/screenshots/) | Capture and frame App Store screenshots. |

Every command has a `make` target, so teammates without taylr can run them too: `make test`,
`make beta` and so on. Each command's page names its target.

To run these with fastlane directly instead, copy `.env.example` to `.env` and fill in your
App Store Connect key and certificates password. `.env` is git-ignored. CI gets the same
values from [GitHub secrets](/docs/guides/ci-secrets/).

## Tools

`.mise.toml` pins every tool the project uses, so everyone on the team, and CI, uses the same
versions: Tuist, your [lint tools](/docs/reference/manifest/#lint), swift-openapi-generator with
OpenAPI, Ruby for fastlane and uv for the press kit. Run `mise install` once after cloning.

The lint and format rules live in `.swiftlint.yml` and `.swift-format`, so you can change them.
Linting also writes the [file header](/docs/reference/manifest/#file-header) from
`Scripts/header.mustache` at the top of every Swift file.

`.devcontainer/` opens the project in Swift's Linux Docker image, so you can build and test
your packages on Linux from VS Code or GitHub Codespaces. There's one for each
[Swift version](/docs/reference/manifest/#swift-versions) CI tests.

Code uses the Swift version that comes with your Xcode, in Swift 6 language mode with strict
concurrency checking. Tests use Swift Testing.

## CI

`.github/workflows/app.yml` runs on pull requests that aren't drafts, and on pushes to `main`
and version branches:

- Builds and tests on macOS for each of your platforms, and every package on Linux, Windows,
  Android and Wasm. A pull request into a feature branch gets a quicker
  [build](/docs/reference/manifest/#build-matrix): the newest Swift on Linux, and macOS.
- Lints in strict mode.
- Runs [`taylr project validate`](/docs/cli/project/validate/) to check `Manifest.swift` is in sync.
- On `main`, uploads a build to TestFlight.

It needs a few secrets; see [Set up CI secrets](/docs/guides/ci-secrets/).

The macOS jobs run on your own Macs for a private repository, or on GitHub's runners for a
public one. Other workflows upload the App Store listing, check the App Store session weekly,
clean up old caches and run Claude Code. Choose the runners, workflows and builds in the
manifest's [`ci`](/docs/reference/manifest/#ci).

## The server

With `--server`, `AcmeServer` is a [Hummingbird](https://hummingbird.codes) server. It starts
with one endpoint, `GET /status`. A `Dockerfile` builds it for Linux.

With `--openapi` as well, the API is described in `openapi.yaml` and the server code is
generated from it with swift-openapi-generator. Without it, you write the routes by hand.

```sh
swift run --package-path Packages/AcmeServer Acmeserverd serve
```

It listens on port 8080, as Hummingbird does by default. Pick another port when you start it
with `--port`. To change the default, edit the fallback in `AcmeServer.swift` and the port in
the `Dockerfile`.
