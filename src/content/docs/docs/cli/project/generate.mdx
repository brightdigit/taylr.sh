Generates the Xcode project for an app and opens it. Run it inside the project after
creating it, and again after pulling changes.

```sh
taylr project generate
```

The Xcode project is generated by [Tuist](https://tuist.dev) from `Project.swift` and isn't
committed, so you never resolve merge conflicts in it.

## What it does

1. Installs the tool versions the project pins in `.mise.toml`, if they're missing.
2. Fixes lint issues it can fix automatically.
3. Generates `Acme.xcworkspace` with Tuist.
4. Opens it in Xcode.

A Swift package has nothing to generate: open `Package.swift` in Xcode instead. See
[`taylr package`](/docs/cli/package/).
`taylr project generate` tells you so.

Teammates without taylr can run `make generate`, which does the same.

## Arguments

### no-open <Badge text="Optional" />

Generate the project without opening Xcode.

```sh
taylr project generate --no-open
```

### strict <Badge text="Optional" />

Fail on lint issues instead of fixing them, as CI does.

```sh
taylr project generate --strict
```
